# 調査中に見つかった不具合候補

不具合候補は再現条件・根拠・影響と確認状況を記録する。仕様判断待ちは `pending-decisions.md`、起票済みのものは対応Issueを参照する。分離作業のついでに挙動を修正しない。

## 2026-10-07：車両・編成作成の入力検査

- 蒸気技術値0・使用期限前・要求速度0：CheckCreateVehicleが成功する一方、費用計算の蒸気技術値による除算でDivideByZeroExceptionになり得る。根拠はGameInfoLogic.csの蒸気判定とLogicUtil.CalcPurchaseCarCost。UI経由での到達可否とシナリオ入力条件は未確認。画面なしの操作窓口で、許可判定と実行の結果が食い違う候補として追跡する。
- 負の要求速度：車両チェックは上限しか見ず、編成速度は二乗平均のため負速度も正の速度になる。非正の編成数量は拒否せず除外される。根拠はCheckCreateVehicle、CheckMakeComposition、CalcCompositionBestSpeed。UIには速度0以上・数量0以上の操作制限があるが本体の入力検証は不足する可能性。負数拒否のADR 0004との適用範囲を確認する必要がある。今回は条件を変えず現状をテストする。
- 未定義の動力・軌間・座席・傾斜enum：既存検査では既知値の条件に該当せず通過し得る。UIが生成する値に限れば通常は出ないが、将来のWeb・共通操作窓口や外部入力では不整合を登録し得る。全操作の入力検証を整備するIssue #23/#28の段階で扱う。正常なゲーム入力の仕様と内部誤りを区別する。

上記は車両・編成の判定理由分離の対象外。モデル単体での再現結果は末尾に記載する。UI到達性と別Issue起票の必要性は後続調査で確認する。

## 2026-10-07：車両開発の確認文と編成の説明

- 車両開発確認文：VehicleDevelopViewModelの確認文は円単位まで含むAppendMoneyUnitの後に「拾万円」を追加するため、「円拾万円」になる。コードから確認済み、実ダイアログ未操作。Issue #27の表示整形に関連する別の表示修正候補。今回の理由分離では変更しない。
- 編成の負数量：検査・作成は非正数量を除外するが、CompositionMakeViewModel.Descriptionは速度・価格を全数量から計算する。負数量を直接設定すると説明と作成結果が不一致になり得る。通常の増減ボタンでは負数量にできず、他の入力経路は未確認。負数入力規則を決める際に説明側も揃える必要がある。

確認結果：VehicleValidationBehaviorTestsで、蒸気技術値0・要求速度0のチェック成功と実行時DivideByZeroException、負速度-40の編成が速度40として成立、未定義enumのチェック通過と編成作成を再現した。車両技術拒否・資金不足・費用計算失敗で資金と登録数は保持される。通常UI・シナリオからの到達性は未確認のままとする。
