# 判断待ち一覧

2026-10-06時点。原作の静的解析から抽出した項目。[Astraの設計仮説](design-hypotheses.md) と独立レビューを判断材料として、質問をまとめる。ここに記載した仕様はまだ変更しない。

| 関連差分 | 判断する内容 | 判断までの扱い |
| --- | --- | --- |
| F06 / F20 | 割当不足時に旧ダイヤ・旧編成を保持するか。必要数の不足判定も合わせて整理する | 現状維持。原作にも失敗途中の状態変更がある |
| F08 / F12 | モード初期投入を余剰数から引くか（Astraは減算しない現状を推奨）。上位技術の運行容量を原作の途中終了まで再現するか | 現状維持。初期投入数と技術の前提関係を分けて判断する |
| F09 / F10 / F11 | 競合シェア、ディーゼル開発条件、目標判定の既存補正を正式な仕様として扱うか | WPF版の既存補正を保持する |
| F15 | 公開購入APIでも負数を拒否するか | 現状維持。原作UIの制限とモデルの計算を区別する |
| F16 | 少数の直接編成にも運行費を課すか。原作の共有変数の再利用は再現するか | 現状維持。費用バランスの判断が必要 |
| F17 / F18 | 廃止を休止か撤去として扱うか。再建時に累計収支・定着率・運行設定をどこまで戻すか | 現状維持。廃止と再建を一組の仕様として判断する |
| F19 / F21 | 原作の引数省略による速度向上費用や、増設の支払額と累計計上額の違いを互換対象とするか | WPF版の引数を保持。HSP実行時の挙動は未確認 |
| F13 | 成長率切替のmyear+100を維持するか、原作コメントの1980年を意図として扱うか | 既に合わせたmyear+100を保持する |

## 作業環境の後続課題

.NET 9はインストール済みSDKで作業を進めるためにユーザーが選んだ暫定方針。PR #4の.NET 10への移行提案には、この判断を返信して解決した。.NET 10への移行・SDK導入はまだ実施していない。ゲーム仕様の判断とは別の後続課題として扱う。
