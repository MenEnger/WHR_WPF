# 技術投資の設定可否と停止

2026-10-08。Issue #28 / #23、PR #57後続。採用判断は[ADR 0027](../decisions/0027-technology-investment-availability.md)。

## 仕様・影響

PR #57時点の5setterは無検査代入、CanはUIの投資可否照会のみだった。ユーザーは、不可部門の非0設定拒否・0停止許可・設定済み投資の自動停止と、通常ディーゼルの電気技術80前提を本体にも適用することを選択した。

投資停止は今後の支払・累計追加を止める。既存累計を失効させず、通常ディーゼル以外の累計開発の条件は維持する。通常ディーゼルの初期開発と+5branchだけ、判定時点の電気技術80を要求する。高度+10branchへ電気技術・電気累計の条件を追加しない。電気branchで同週80に到達すれば、通常ディーゼルも既存累計から開発できるが、停止額は自動再開しない。

設定拒否では本体値を保持し、UIも保持値へ戻り、既存の「投資不可」表示を確認できることを受入条件とする。設定成功時の支払・開発は行わない。未知enum・負額の定義値検査、public field削除、数式・閾値・上限補正、負残高禁止、原子性、新GameEventはこの変更へ混ぜない。

## 仕様・影響レビュー

Astraの初回指摘に従い、案にあった全動力Can開発guardを撤回した。これは蒸気期限後等の累計開発と高度ディーゼルへ、ユーザー回答外の新規則を広げるためである。UI拒否の表示復帰も受入条件へ追加した。訂正後、Astraが仕様・影響を承認。追加のユーザー判断は不要と確認した。

## 設計と設計レビュー

5setterは部門と要求額を持つTechnologyInvestmentFailure/専用例外で、不可の非0設定を代入前に拒否する。0は許可し、対象部門だけ更新する。額が変わった場合だけPropertyChanged(nameof(weeklyInvestment))を一回通知し、拒否・同値設定は通知しない。

不可部門を停止するhelperは、値型InvestmentAmountの変更前snapshotとの差で一回通知する。停止境界は次の3か所に限定する。

1. 週次支払直前：不可部門のその週の支払と累計追加を止める。
2. 動力・新企画開発後：到達した上限/全技術完成を反映する。既存360/990停止も、開発前snapshotとの差で同じ通知へ含める。
3. Year更新直後、NextYear前：蒸気期限到達を反映する。到達週の支払/開発は従来の旧年条件で行い、次週以降は支払わない。

既存AccumulatedInvest通知の順序を移さず、その後の開発による停止を新しい通知で表示する。年次処理の途中失敗でも、Yearと停止済み額は残る。停止通知subscriberの例外も伝播し、変更済み額を保持して、その後の支払/年次等へ進まない。finallyで未到達処理を補完せず、ADR 0019の部分失敗契約を維持する。

public field/Yearの直接変更やモード再適用へ常時追従する保証は追加しない。設定操作と上記週次境界で再検査する。

VMは投資額通知も受けて既存再通知を行う。5setter共通の小さいhelperで専用拒否のみ捕捉し、binding書込後のDispatcher.DataBindへ再通知を予約してmodelの保持値に戻す。既存のCan/Visibilityと投資不可labelを利用する。ダイアログやXAML変更、既知の蒸気IsEnabled誤名修正は追加しない。

Astraの別段階の設計レビューで承認。仕上げでは成功側も実ComboBoxで確認し、新しい通知によるItemsSourceの再通知が選択を壊さないことを検査する指摘を受け、既存VM反射試験を実選択の試験へ変更した。

## 試験と検証

- Core18件を追加：5部門の拒否/0/同値、支払前停止、通常ディーゼル79/80、同週解放、高度だけの継続、年末停止/年次途中失敗、開発停止通知、通知失敗の途中状態。拒否payloadとobserverが読む額・通知回数を検査する。
- 既存5部門試験は可の前提を試験内で整え、対象以外/資金/累計/技術保持、未知enum受理の現状、変更時の通知を検査する。未知enum受理を新規採用した意味ではない。
- 既存の週次全部門課金とディーゼル数式/イベント試験は、対象の前提だけを個別に整え、数式とイベント期待値を保持する。共有Game()/WeeklyEventFixtureは変更しない。
- WPFは既存接続試験を5部門の実ComboBox選択/通知回数へ更新し、拒否時の選択復帰と年末自動停止の2件を追加。Window.Closeで既存listenerを解放する。
- Cloud Linux / .NET9.0.318：Core317・Scenario84、計401件成功（失敗/skip0）。最終Core差分も再実行して成功を確認した。
- WPFテストprojectのクロスビルド成功（警告/エラー0）。WPFのWindows実行は未実施で、ビルドを実行成功の代用にしない。Windows全体の予定件数は564（Core317/Scenario84/WPF163）であり、実行結果ではない。

GitHub Actions整備はユーザー指示で撤回し、[Issue #58](https://github.com/MenEnger/WHR_WPF/issues/58)へ低優先度・対応予定なしとして記録した。Windows全体検証はユーザー側CIの最新head結果を待つ。約2分の定期監視は利用可能なautomationの最短1時間制約により設定できないと報告済み。作業中はレビューを直接確認し、Codex・Copilot最新head完了、Astra仕上げと必要なWindows検証等が揃うまでマージしない。
