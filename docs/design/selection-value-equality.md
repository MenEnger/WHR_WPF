# 表示名に依存しない選択肢の同一性

2026-10-08。Issue #27の第二段階。

## 仕様検討

TaihiViewComponentは待避線enum、LaneNumViewModelは線数、RailTypeViewModelは軌道・nullable軌間・電化で一致を判定する。Captionの変更・重複は選択肢の意味を変えない。型付きEqualsだけでなくWPFが使うobject.EqualsとGetHashCodeも同じ値に揃える。nullや別種のオブジェクトは一致しない。

入力・計算・設備設定は変更せず、異なるインスタンスでも同じ値なら一致するという同一性の変更だけを行う。表示名と選択肢の個数・順序は維持する。基底表示部品や他の選択肢へ一律に拡張しない。

## 影響確認

3型は既にIEquatableを実装しているがobject.Equalsをoverrideしていない。型付き比較はCaptionを含み、object比較は参照一致になる。製品の選択はConstructWindowのSelectedValue（ValuePath指定なし）3項目とTaihisenChangeWindowのSelectedItemが対象。リストgetterは新しいインスタンスを返す場合があり、型付きだけの更新ではWPFの値照合に届かない。

全Equalsと該当バインド、既存初期値選択を確認する。3型をハッシュキーに使用する製品コードは現状見つからない。値プロパティは可変のため、HashSet/Dictionaryへ入れた後に値を変更しない必要があることを設計判断へ記録する。Caption変更だけではhashも変わらない。

## 検証計画

変更前に型付き比較とobject比較の違い、Caption違いの現状を固定する。変更後は同値/別値/null・別型・同値hash・Caption変更を代表ケースで確認する。実WPFバインドで、Captionを変更した同値の別インスタンスからの初期選択、同じCaptionを持つ別値の選択、UIからVMへの書戻しを確認する。三型の意味と二種類の既存バインド方式を対象とし、全値の組合せを増やさない。金額/設備の成功・拒否は既存試験を再利用する。

## 仕様・影響レビュー

Astraは値ごとの比較、公開3型の比較意味の互換性変更、実バインドの通常・休止路線の初期選択を確認する条件で承認した。旧実装の基準試験は型比較3件・WPF2件が成功した。通常と休止路線の初期選択は旧実装でも成功する。一方、Captionを変更した同値の別インスタンスでは建造画面の選択が外れ、待避線画面は旧選択を維持する。後者もVMに保持する選択と表示との一致を検証する。

## 設計

各型の既存の型付きEqualsからCaption条件だけを除く。object.Equalsは対象型かを確認して型付きEqualsへ委譲する。GetHashCodeは待避線enum、線数、またはHashCode.Combine(軌道・nullable軌間・電化)を使う。リニアでも軌間と電化を省略せず、値の正規化はしない。別型・nullは不一致とする。

公開型・プロパティと可変性は維持する。公開APIを削除しないが、Captionによる不一致とobjectの参照比較が値比較へ変わり、ハッシュ集合で同値要素が重複排除される互換性変更がある。値をハッシュキーに使用中は値を変更しない。製品でその使用は見つからない。継承可否や既存リスト生成・Caption生成・XAMLは変えない。比較用の共通基底クラスやリストキャッシュは追加しない。

検証は3型の比較を各値フィールドの差、nullable軌間、null・別型、Caption変更・重複と同値hashで確認する。実ConstructWindowのSelectedValueとTaihisenChangeWindowのSelectedItemをSTA上で使用する。通常/休止の初期選択、同値でCaptionが異なる別インスタンスの照合、同Captionで別値をUIから選んだ時のVMへの書戻しを確認する。選択肢に存在しない線数の復元は別の既存問題として記録し、この比較変更には混ぜない。

## 設計レビュー

Astraが設計を承認した。比較契約の一貫性、公開型の影響、二種類の実バインド検証、過剰な共通基盤を追加しない構成に修正必須の指摘なし。承認後に実装へ進んだ。

## 実装・検証結果

3型の型付き比較からCaptionを外し、object比較と値hashを追加した。基底型・XAML・リスト構成と計算は変更していない。比較5件と実WPF3件を追加し、既存試験を含む全515件成功・失敗0・skip0（隔離出力artifacts/selection-tests、UseSharedCompilation=false）。変更前の型比較3件と実WPF2件の基準実行も成功した。

実バインドは値を照合した後もcloneをSelectedItemへ保持する場合がある。最初の試験がItemsSource内の参照への正規化まで期待して1件失敗したため、選択indexと値一致を契約とし、別の目標値への選択とVMへの書戻しを確認する試験へ修正した。製品に参照正規化を追加しない。全3値の路線規格比較、null/別型・同Caption別値・Caption変更後の同値hashと二種類の実バインドを確認済み。採用判断はADR 0021。
