# シナリオ読込診断の構造化

2026-10-07。Issue #25の残作業。実装前の仕様・影響・設計記録。

## 仕様検討

ファイル欠落・アクセス失敗、値の欠損・数値不正、CSV書式・列不足・参照番号不正、モード設定不正を、理由コードと出典情報を持つ例外で呼び出し側へ伝える。UIはコードから案内を生成し、内部例外のメッセージ全文を画面文言にしない。

ゲームの数式・費用・運行設定、許容している省略・値補正は変更しない。ファイル解析と表示責務の分離が目的であり、新たなシナリオ仕様や全項目の厳格検証は追加しない。不正な版・基準年の既存構造化例外とUIの終了方針は維持する。他の読込失敗は画面遷移せずメニューへ戻る。

## 影響確認

- `ScenerioLoadUtil.LoadFile` の呼出先は `ScenarioPresentation.LoadScenario` とテスト。I/O・数値解析の例外型を検査しているテストは、理由コードとInnerExceptionへ更新する。公開APIの例外型変更は外部のcatchとの互換性に影響する。
- 公開 `CreateModeList`・`CreateWarModeList`・`ExtractModProperty` 等の単独呼出は契約を維持する。構造化はファイル読込の境界で行う。
- 判定順はindex.mod読込・設定値の消費と補正→地図確保→town→line→longway→diagram→モード解析。まとめて事前検証せず、元の値消費位置で診断する。
- 地図コールバックは利用側の処理であり、その例外をシナリオ解析例外で包まない。画像スナップショットとファイル解放の既存検証を維持する。
- index.modは読み込んだ行を使い続ける。後からファイルが置換されても再読込しない。途中状態は成功結果として返さない。

欠損の診断対象は従来も失敗していた必須値に限る。地図読込・予期しない例外も、UIでは汎用案内を表示し、詳細はログへ記録する。

## 設計

1. WPF非依存の `ScenarioReadException` に理由コード・ファイルパス・解析段階・任意の行番号と項目・元例外を持たせる。値・項目が判明しない場合は推測で埋めない。
2. 設定数値・必須文字列は元の消費位置に小さなhelperを置く。hojo/message欠損はそこで検出し、NullReferenceExceptionの一括捕捉は行わない。数値の欠損・書式・範囲超過を分類する。
3. ファイルI/O・CSV・モードごとに限定した例外捕捉を行う。外側から全Exceptionを変換しない。ファイル引数のプログラム上の誤りや地図コールバックは変換対象外。モード内で入力から発生する軌間・動力・重複キー等のArgumentExceptionはその段階で分類する。
4. CSVの行番号はレコード開始の物理行とする。数値変換・列アクセス・参照解決まで同じ行情報を持つ。不正引用はTextFieldParser.ErrorLineNumberを利用する。列不足と参照先不正は可能な範囲で区別し、終端不足は書式不正として扱う。
5. モード診断は最低限index.mod・モード解析段階を特定する。特定可能な項目には項目名を付け、配列の失敗から項目を推測しない。
6. UI formatterは日本語の案内と出典を組み立てる。元例外は診断用に保持し、UIのログへ出す。ダイアログと終了判断はUIに残す。

理由コードはファイル欠落、アクセス拒否、その他I/O失敗、必須値欠損、数値書式不正、数値範囲超過、書式不正、項目不足、参照先不正、設定不正を区別する。解析段階は設定・駅・路線・乗継・運転系統・モード。行番号は1始まりとし、取得できない場合はnullとする。CSVの項目不足と終端不足は元のアクセス位置で検出する。設定項目には特定できるキーを付け、モードではブロック番号を付ける。元から発生する例外はInnerExceptionへ保持し、明示的な必須値検査は元例外なしを許容する。

単独helperの公開契約を保つため、読込専用の診断コンテキストをprivateな経路で渡す。コンテキストなしの公開helperには新たな検査・例外変換を加えない。捕捉位置は入力を消費する小さな処理に限定する。CSV行の変換は既存順を維持して行単位で行い、参照番号と列アクセスを別の小さなhelperで診断する。広い範囲のArgumentException、NullReferenceExceptionは捕捉しない。

## PR #35レビュー対応：永続診断ログ

2026-10-07。WinExe通常起動ではConsole.Errorが保存先にならない指摘を確認した。構造化例外と予期しない例外の2経路を、UIホストがファイルへ記録する。既存version/basicyear検証例外の終了経路は今回の対象外。モデル・解析側にlogger依存を加えず、メニューへ留まる方針を維持する。仕様・影響レビューはAstraで実施し、致命的不足・追加のユーザー判断なし。

設計はView側の小さな `ScenarioReadDiagnostics.TryWrite(Exception, string filePath = null)` とする。既定保存先はLocalApplicationData/WHR_WPF/Logs/scenario-read.log、テストは一時保存先を指定する。日時（UTC）、理由・段階・ファイル・項目・行・モード番号とex.ToString()を追記する。成功時だけ絶対保存先を返す。ディレクトリ作成・追記のI/O・権限失敗時はnullを返す。元の読込例外を置き換えず、ログ失敗を再び記録しない。

UIは元の日本語案内に、成功時のログ保存先、失敗時の保存不可案内を追加する。内部例外の文言は表示しない。ログの成功内容・追記・親ディレクトリ作成失敗・ファイル追記失敗と案内の成功/失敗を検証する。今回の2経路向けの保存であり、全アプリのログ基盤や設定UIは追加しない。

空白行の指摘は.NET 9の実テストで再現せず、スペース・タブ・全角空白の後のレコード開始行が正しいことを追加確認した。パーサーと補正の挙動を変えず、テストと結果で回答する。
