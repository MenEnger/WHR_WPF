# 週次途中失敗の契約と通知分離の最終確認

2026-10-07。Issue #26の最終段階。

## 仕様検討

通知と想定内拒否の表示分離では、週次APIの現状を維持する。NextWeek成功時は発生順のGameEventリストを返し、イベントは発生時点の値を保持する。途中例外ではそれまでの状態変更を巻き戻さず、失敗した週のGameEventリストは返さない。先に発生したPropertyChangedや成功週後のUI更新を取り消したり抑制したりはしない。期限超過はGameOverExceptionの構造化データで伝わる。例外発生以前の通知を例外に追加したり、成功結果と推測して補ったりしない。

四週送りは成功した先行週を巻き戻さず、後続週が失敗した場合はUIの最後の集約通知表示へ到達しない。モデルを再実行すると別の週へ進み得るため、失敗した操作の自動再試行や安全な再実行を契約に含めない。

これは現状固定の採用判断であり、途中イベントを返す結果API・原子性・UIの例外捕捉範囲を変更する判断ではない。後の共通操作窓口 #28で操作結果と診断境界を設計する際は、この現状を明示して仕様変更を区別する。

## 影響確認

製品コードと公開APIは変更しない。NextWeek/一週/四週の処理順・乱数・通知・例外型とUIのtry範囲も維持する。既存テストを証拠に最終契約を記録し、同内容の回帰試験を重複追加しない。

Issue #26の週次23通知、車両/編成作成、編成適合、設備操作、在庫不足、運行初期拒否、資金不足/期限超過、建造拒否は構造化済み。残る算出式不在・未定義値・引数範囲・不整合の例外は内部診断として区別し、すべてを同じ拒否型へ移さない。Money/enum表示名/Line.Captionは #27、プロジェクト抽出と操作窓口は #28、乱数と操作列は #29の対象。

週送りのtry外例外、独自画面での拒否未捕捉、モード適用不整合の保存未接続、フリーモード終了文言は既知の別判断として残す。Issue #26の文言分離完了を、全UIエラー処理や原子的操作の完成と表現しない。

## 検証計画

WeeklyNotificationBehaviorTestsの期限途中失敗・四週のモデル呼出ループ失敗とイベント順序/不変性、WeeklyCurrentBehaviorTests/GoalDeadlineRegressionTestsを根拠にする。実UIの集約表示へ到達しないことはGamePageViewModelの制御フローを静的確認した根拠と区別する。全Model/Utilの文字列生成と受け取り側を再確認し、未移行の想定内拒否がないかAstraで照合する。文書のみの変更なので既に成功した全495件を意味なく再実行せず、必要な追加検証がレビューで判明した場合に実行する。

仕様・影響レビュー（Astra）：承認、設計へ進行可。想定内拒否の移行漏れなし。失敗週のGameEvent未返却とPropertyChanged/UI更新の違い、四週モデル試験と実UI静的確認の違いを文書へ明記した。GitHub本文はレビュー側で認証により取得できなかったため、親が取得したIssue完了条件との照合は親で行う。
