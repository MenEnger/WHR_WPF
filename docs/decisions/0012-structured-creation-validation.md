# ADR 0012：車両・編成作成の判定理由を表示から分離する

- 状態：採用
- 日付：2026-10-07
- 関連：Issue #26、#23、#28

## 背景

車両・編成チェックのtupleに日本語文章が入り、作成拒否の例外Messageも直接表示されていた。UIの差し替えや画面なしの操作では、理由と対象値を文章解析せず扱える必要がある。

## 判断

検査結果を理由enumと値の不変recordへ変更する。車両は入力enum・要求速度・上限・期限年を、編成は不一致のenum値の不変集合または計算速度・最低値を保存する。可否は理由Noneから導出する。モデルや車両の可変参照を保持しない。

想定内の作成拒否は専用のInvalidOperationException派生型に結果を保持する。UIでチェック結果と拒否例外を日本語へ変換する。車両の実行時汎用文と検査時詳細文の違い、編成の同一案内、成功時の旧空文字/nullの表示側の差を維持する。

判定順・短絡評価・数量選別・費用・実行時の再判定と再列挙を維持する。資金不足・引数誤り・内部例外を一律に拒否結果へ変えない。未知enumや負数等の入力規則改善は別の判断とし、候補をdocs/bug-notes.mdへ記録する。

## 代替案

- tupleの文字列を残して別にコードを足す：表示責務が本体に残り二重管理になるため採用しない。
- チェックと実行の理由文章や成功表現も統一する：現在の表示とAPI整理を同時に変えるため今回は採用しない。構造化結果の成功は理由なしとし、旧文章の差は表示側のみへ残す。
- 全操作の例外を同時に置換する：編成適合・割当途中失敗・週次処理の状態契約を別に調べる必要があるため段階化する。

## 影響

公開チェックAPIの戻り値変更は破壊的変更。分解代入や文字列参照を使う外部利用者は新結果とformatterへ移行が必要。作成拒否の具体例外型・Messageも変わる。InvalidOperationExceptionでの捕捉互換は維持するが、厳密型比較・日本語Message依存の互換は終了する。内部診断MessageはUI文章の契約ではない。

検査結果取得後のモデル変更からの不変性、実行時再判定、全理由・境界・優先順・拒否時の状態とUI接続を検証する。実ダイアログ操作は今回未実施で、主要導線のE2EはIssue #37へ残す。

仕様・影響、設計の各レビューと検証記録はdocs/design/vehicle-validation.mdを参照。
