# ADR 0011：週次イベントと表示文章の分離

日付: 2026-10-07
状態: 採用。ADR 0006の継続。Issue #26の第一段階、関連 #28。

## 背景と判断

NextWeekは23箇所で日本語の通知を組み立て、List<string>として返していた。UI変更やハーネスの検証が通知文に依存するため、通知を不変のデータとしてモデルから返し、UIで現在の文章を生成する。

動力の完成・速度改良・費用低下を、実行した分岐の種別と前後の技術値で表す。技術値をすべて速度と解釈したり、その大小から種別を再判定したりしない。同週に速度改良と費用低下が連続する場合は、中間値をそれぞれのイベントに残す。新企画の完成は企画種別と運行容量の前後値、蒸気終了は年、戦時開始/終了は期間と貨物係数、目標達成は実行中期限と延長期限を保持する。

sealed recordを使い、モデルの可変参照をイベントへ入れない。週次・年次の既存通知追加位置を置換し、数式・条件・更新順・回数・投資停止・期限優先順位を維持する。UIのWeeklyEventFormatterが既存23文章と区切りを生成する。未対応のイベントや組合せは明示的な例外とし、通知を黙って消さない。

## 代替案と影響

- 本体に文字列互換wrapperを残す：表示責務が本体へ残るため採用しない。公開NextWeekの戻り値はList<GameEvent>へ変わり、外部の文字列利用側は移行が必要となる。
- 一つの汎用イベントに任意フィールドを詰める：無関係な値や欠損が増えるため、イベントごとに必要なデータを持つ型を使う。
- 週次結果と失敗を新しい結果型へ統合する：状態の巻戻しや通知の返却範囲の判断が必要となるため、表示分離と混ぜず後続へ残す。

期限等の途中失敗は従来の例外を投げる。変更済み状態は巻き戻さず、例外発生前の通知も返さない。四週送りの途中失敗では先行週の通知も通常表示されない現状を維持する。一週送りのtry範囲の問題、ゲームオーバー文章、乱数、操作拒否・車両/編成の判定理由は今回の対象外。

## 検証と残る範囲

仕様・影響と設計をそれぞれAstraが実装前にレビューした。実装前の2ケースで19通知の同週発生順と中間値、期限失敗の途中状態を記録した。構造化後は各イベントの種別・前後値・順序・不変性、UIの23文章と複数週の区切りを検証する。既存の数式・状態テストを維持する。

実ダイアログは操作せず、UIの接続は差分、表示整形は自動テストで確認する。操作拒否・検証理由と部分失敗のAPI整理が残るためIssue #26は未完了。別プロジェクト抽出と共通操作窓口のIssue #28も残る。

全321件成功（失敗・スキップ0）。新規40ケースは、変更前に確認した2ケースを含む。週次・目標期限・表示の対象100件では23文章の完全一致、空通知と複数週の区切り、未対応イベントの拒否、同週の中間値と容量、戦時解除、後の変更からの不変性、途中失敗の変更済み状態を確認した。Astraレビューで製品の修正必須指摘なし。テストのリニア分岐と区切りの誤期待は、旧仕様へ合わせて修正した。
