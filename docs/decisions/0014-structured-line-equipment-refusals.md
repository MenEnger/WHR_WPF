# ADR 0014：路線設備の操作拒否を表示から分離する

- 状態：採用
- 日付：2026-10-07
- 関連：Issue #26、#28

## 背景

路線設備8操作の冒頭拒否は日本語InvalidOperationException.Messageを直接返す。UI交換と画面なしの操作に備え、想定内拒否と内部エラーを文章に依存せず区別する。

## 判断

既存Can判定と操作APIを維持し、8冒頭拒否だけを理由enumと不変recordを持つ専用のInvalidOperationException派生型へ移す。路線名・存在状態と操作に必要な設備値を保存し、不使用値はnull。GameInfo・費用・可変モデル参照は収集しない。

理由は既存の操作単位の拒否とし、細かい原因を再分類しない。分岐内で必要値を直接保存し、汎用helperや新しい可否APIは追加しない。Viewのformatterが現行8文章を生成する。ViewModelBaseは一般例外より先に専用型を捕捉する。

内部レーン異常、建設の引数拒否、資金不足、割当、週次失敗は別の契約として維持する。待避線画面が独自処理で操作拒否を未捕捉とする既存問題も、今回の文言分離では変更せず不具合候補へ記録する。

## 代替案

- 日本語Messageを本体へ残す：表示責務が残るため不採用。
- Canを全て理由付き検査へ作り直す：既存の判定条件と新しいサブ理由の契約を同時に変えるため今回は不採用。
- 全設備状態・費用を共通snapshotへ保存：現在の拒否理由に不要な情報と依存が増えるため不採用。
- 全失敗を同じ拒否型へ変える：内部異常と想定内拒否を区別できなくなるため不採用。

## 影響

操作シグネチャ・Can API・InvalidOperationExceptionでのcatch互換は維持する。厳密な例外型比較と日本語Messageへの依存は移行が必要。条件・費用・支払・設備/運行変更・途中失敗の順序は変えない。

責務分離を前提に可読性・保守性を重視し、各分岐と必要状態の対応を近くに保つ。成功・資金不足の既存テストを再利用し、拒否・snapshot・表示を限定追加する。仕様・影響・設計・検証はdocs/design/line-equipment-refusals.mdを参照。実ダイアログ未操作、主要導線E2EはIssue #37。
