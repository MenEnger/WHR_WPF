# ADR 0013：編成適合の拒否理由を表示から分離する

- 状態：採用
- 日付：2026-10-07
- 関連：Issue #26、#28

## 背景

路線・系統への編成適合拒否はCompositionNotAppliedExceptionの日本語Messageを画面へ直接渡す。画面なしの操作やUI交換では文章解析に依存しない理由が必要。

## 判断

void検査と既存例外型を維持し、例外に理由enumと拒否時の値の不変recordを保存する。軌道、軌間、電化、蒸気期限について該当段階の比較値だけを保持し、不使用値はnull。路線名は識別補助でnullも許容し、現行文章には追加しない。可変モデル参照や系統全体の情報は保持しない。

既存分岐に理由と保存値を直接対応付ける。編成のgetterを先読み・再読込しない。任意ICompositionの追加getterによる新しい失敗経路を避けるため編成名は収集しない。短絡・検査順・系統順・引数/内部例外と状態変更を維持する。

UIが既存5文章を生成する。両ダイヤ設定VMと実行時の例外処理で変換し、可否判定は既存の例外型で判断する。責務分離を前提とした可読性・保守性のため、新しい検査API・成功結果型・汎用例外層は追加しない。

## 代替案

- 日本語Messageを残して理由も追加：本体に表示責務が残るため不採用。
- 全拒否を共通の結果APIへ変更：今回の5理由に対して呼出側の変更が広く、成功表現も増えるため不採用。
- 理由別のrecord型階層：必要な比較値が少なく、nullable値の単一recordで十分に追えるため不採用。

## 影響

検査APIのシグネチャ、CompositionNotAppliedExceptionとInvalidOperationExceptionでの捕捉互換は維持する。公開stringコンストラクタと日本語Messageの互換は終了する。直接構築する外部利用者、および外部派生例外でbase(message)を呼ぶ実装は移行が必要。

割当不足・途中失敗・費用の変更は含めない。検証と各段階レビューはdocs/design/composition-compatibility.md、別の不具合候補はdocs/bug-notes.mdに記録する。実ダイアログのE2EはIssue #37へ残す。
