# ADR 0019：週次途中失敗は現状契約を維持する

- 状態：採用
- 日付：2026-10-08
- 関連：Issue #26、#28、ADR 0011

## 背景

通知と想定内拒否を表示文から分離した。Issue #26の完了前に、週次処理が途中で失敗したときの状態とイベント返却範囲を、既存テストに基づいて確定する。

## 判断

NextWeekは成功時だけ、その週の発生順のGameEventリストを返す。途中例外では、既に変更した状態を巻き戻さず、失敗週のリストも返さない。期限超過は既存GameOverExceptionの構造化データで伝える。

先に発生したPropertyChangedは取り消さない。四週送りで後続週が失敗した場合も成功した先行週の状態とUI更新は残り、最後の集約GameEvent表示には到達しない。成功週のリストを受け取った呼出元が保持することは禁止しない。失敗した週の未返却イベントを後から補完したり、同じ操作を自動再試行したりする契約はない。

これは現状固定の判断であり、原子的操作や失敗時イベント返却を完成させる判断ではない。#28の共通操作窓口で結果・診断の境界を設計する際には、この契約を明示し、変える場合は別の仕様判断と回帰検証を伴わせる。

## 代替案

- 状態を巻き戻す：路線・編成・人口・投資・日付等にまたがる原子性の設計が必要で、表示分離の範囲を超える。
- 途中イベントを例外へ格納する：すべての失敗経路と返却順・回数・UI表示の仕様が変わるため、操作窓口の設計へ分ける。
- 新しい結果APIへ全例外を統合する：引数誤りや内部診断まで想定内拒否と同一視せず、必要な境界を後で設計する。

## 影響と検証

製品コード・公開API・UIのtry範囲は変更しない。既存の週次イベント順序・不変性、期限途中失敗、四週モデル呼出ループの部分状態を検証根拠にする。実UIの集約表示はGamePageViewModelの制御フローの静的確認であり、ダイアログ操作試験とは区別する。

全495件成功はPR #44の製品・試験状態の検証結果を参照する。今回の文書変更で試験を再実行しない。最終照合はdocs/design/weekly-failure-contract.md。

Issue #26は通知・判定・想定内拒否のデータ化と表示分離を完了とする。内部不整合・引数範囲・シナリオ診断は想定内拒否と区別し、すべてを構造化し直さない。表示整形・enum表示名・Captionは #27、ゲーム本体/共通操作窓口は #28、乱数/操作列は #29で扱う。週送りtry外、独自画面の未捕捉、モード適用診断保存、フリーモード終了文言等の既知問題は別の判断として残る。
