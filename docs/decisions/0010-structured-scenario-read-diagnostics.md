# ADR 0010：シナリオ読込診断の構造化

日付: 2026-10-07
状態: 採用。ADR 0006・0008・0009の継続。関連Issue #25・#28。

## 背景と判断

版と基準年以外の読込失敗は、I/O・数値変換・配列アクセスなどの例外をそのまま伝え、メニューが内部例外の文言を表示していた。UIを交換しても同じ解析処理を使えるよう、`LoadFile` の入力失敗をWPF非依存の `ScenarioReadException` で伝え、UIで日本語の案内とログを生成する。

理由はファイル欠落、アクセス拒否、その他I/O失敗、必須値欠損、数値書式不正、数値範囲超過、書式不正、項目不足、参照先不正、設定不正に分ける。出典はファイル・解析段階に加え、特定できる行・項目・モード番号を持たせる。不明な情報を推測で埋めない。CSVはレコード開始の物理行、モードは1始まりの番号とする。元例外をInnerExceptionに保持し、消費位置で明示的に検出する必須値欠損は元例外なしを許容する。

値の消費順とファイルの確保順を維持する。必須値は従来も失敗していた箇所に限り、空数値は書式不正とする。省略可能な値・補正・prefixによるキー照合・ゲームの計算は変更しない。地図のコールバックはUI側の処理なので例外を変換せず、既読index.modを再読込しない。

CSVはファイルごとに読み取った文字列をパーサーと物理行の計数で共有する。行番号のためにファイルを再読込しない。空行を飛ばすパーサーの位置から、同じ内容のレコード開始行を求める。従来も文字コード判定で全バイトを読んでおり、巨大ファイル向けのストリーミング仕様は今回の対象外とする。

## 代替案と影響

- 全例外を外側で包む：プログラムの不具合と入力不正を混同し、地図コールバックの契約も変えるため採用しない。入力の消費位置で限定した捕捉・検査を行う。
- 全ファイル・設定を事前検証する：複数不正の優先順や解析途中のファイル変更の影響が変わるため採用しない。
- 汎用parserや新しい読込サービスを導入する：今回の責務分離には不要。小さな診断コンテキストとhelperで対応する。

公開 `LoadFile` の入力失敗の例外型は変わるため、外部で元の例外型をcatchしているコードは対応が必要となる。公開の単独解析helperは従来契約を維持する。地図・予期しない例外の案内もUIの汎用文言にし、詳細はログに残す。不正な版・基準年の表示と終了方針は維持し、それ以外はメニューに留まる。

PR #35レビューで、WinExeのConsole.Errorだけでは通常起動時に診断を保存できない点を確認した。UI側がLocalApplicationData/WHR_WPF/Logs/scenario-read.logへUTC日時・構造化出典・元例外とスタックを追記する。成功時は保存先を案内し、ディレクトリ作成・追記のI/O・権限失敗は元の読込案内を保って保存不可を表示する。LocalApplicationDataが取得できない場合も保存不可とする。モデルへlogger依存を加えず、独立したログ基盤や設定UIの導入は見送る。

## 検証方針

仕様・影響と設計をそれぞれAstraが実装前にレビューした。正常なデータ・参照・省略・補正・UTF-8/Shift_JIS・画像寿命を維持し、解析失敗の分類と位置、複数不正の優先順、地図コールバックの例外同一性、解析段階間の削除・置換、内部例外の画面文言への混入を回帰テストで確認する。結果はPRと振り返りに記録する。

現状失敗7ケースを変更前に確認し、診断・互換性の73ケースを追加した。全272件成功。Astraのコードレビューで修正必須の不具合なし。網羅性の指摘に対応し、アクセス拒否の実経路、warmode不正、貨物終端−2、前方一致も追加検証した。実ダイアログ・メニュー遷移・終了の操作は未実施で、表示整形・読込境界・既存WPF描画は自動テストで確認した。

PRレビュー対応で空白3ケースと診断保存6ケースを追加した。空白行の指摘は.NET 9で再現せず、スペース・タブ・全角空白の後の物理行番号を維持した。ログは一時保存先だけで成功内容・追記・作成失敗・追記失敗とUI案内を検証し、ユーザーの実ログを変更しない。

対応後のAstra仕上げレビューで修正必須指摘なし。全281件成功（失敗・スキップ0）。

本体プロジェクトの抽出（#28）、状態操作の通知・拒否理由（#26）、表示文字列の分離（#27）、シナリオ形式の再検討は別の作業として残す。
