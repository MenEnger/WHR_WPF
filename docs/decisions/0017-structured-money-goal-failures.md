# ADR 0017：資金不足と期限超過を表示から分離する

- 状態：採用
- 日付：2026-10-07
- 関連：Issue #26、#28

## 背景

SpendMoneyとCheckAchievementが日本語Messageで資金不足・ゲーム終了を伝えている。UI以外の呼出元にも、文章に依存せず原因と判定時の値を渡す。

## 判断

資金不足は要求額と判定時資金の2つのlong、期限超過はDeadlineExceeded理由と判定年・実行中期限の2つのintを不変recordにする。既存例外型・継承は維持し、各recordを受け取るコンストラクタと取得専用Failureに変更する。内部Messageは英語とする。

比較前のMoneyを局所保存して拒否データへ使用し、成功時の減算・通知は維持する。期限超過の条件と優先順は維持し、初期設定の期限や目標の有無は追加参照しない。不足額の演算や目標状態の推測は加えない。

Viewのformatterが既存2文章を作り、全6catchを接続する。画面の確認・閉じる・終了処理と週送りのtry範囲は変更しない。フリーモード終了でも同じ理由と文章を維持する。

## 代替案

- 日本語stringコンストラクタを互換用に残す：Modelから表示責務がなくならないため不採用。
- 全操作の結果型・週次通知返却も同時に変更：途中失敗契約の判断とAPI設計が必要なため別段階とする。
- 不足額を算出し、フリーモード終了理由を別にする：数値の異常状態や文言の仕様が変わるため今回は不採用。

## 影響

既存例外型catchの互換は維持する。stringコンストラクタと日本語Messageの互換は終了し、外部派生例外のbase(message)にも移行が必要。リポジトリ内の全生成・表示先を確認した。

負額・負資金や週次途中失敗の現状を保持する。週送りの例外がtry外で発生する既知の候補と、フリーモード終了文言は後続判断とする。設計と検証はdocs/design/money-goal-failures.md。責務分離に必要な少数の型と表示境界に限定し、既存の操作拒否・期限境界・途中状態テストを再利用する。
