# ADR 0003: 設備を保持する休止と有料再建

日付: 2026-10-06
状態: 採用（ユーザー判断）

## 決定と根拠

ユーザーの「廃止前の設備を維持する休止」「原作寄り」に従い、単線の削減操作を休止にする。原作は廃止後にも規格を保持し、再建には建設費を払う。無料再開の案は採用しない。

明示的なIsSuspendedで未建設と休止を区別する。休止直前の速度、改良回数、軌道、軌間、電化、レーン数、待避線、ダイヤ種別を保持し、直接・系統の編成と本数を解除して余剰へ一度だけ返す。運行・週次旅客・貨物・運行容量・維持費は停止する。休止前の週収支は次の週送りまで前週の記録として残す。累計収支と定着率は保持する。

複線以上は従来どおり削減し、単線になってから休止する。休止経由の系統割当は状態変更前に拒否する。モード初期化は前の休止フラグを消す。

UIは「路線削減・休止」「休止中（設備保持）」「路線再建」に変更する。休止中も設備を表示し、再建画面は保存規格を初期選択する。建設費が必要で運行編成は再設定することを表示する。

再建は従来のConstructを使い、建設費を資金と累計収支へ反映する。速度改良回数は従来どおり0へ戻る。原作の累計収支上書き・定着率補正までは今回採用せず、F17の未決事項とする。設備保持を判定するために未建設路線の規格値を推測する案は採用しない。

## 検証

SelectedBehaviorTestsで設備保持・編成返却・休止中の週次処理・割当拒否・有料再建と資金不足時の状態保持・画面の状態と設定引継ぎを確認する。実装と網羅はAstraの仕上げレビュー対象とする。

検証結果: 全159件成功。回収6モード48週後の人口照合も全60都市一致。Astraが実装・状態変更テスト・採用判断との整合をレビューし、追加P1/P2指摘なし。0購入の債務時失敗はレビューで検出し、早期returnとテストで解消した。UI実画面の操作は未確認で、ViewModelとXAMLビルドによる検証。
