# ADR 0002: 明確な週次処理と売却・リセットの移植漏れを修正する

日付: 2026-10-06
状態: 採用（原作解析・採用判断をAstraが独立レビュー済み）

## 背景

[原作比較](../original-analysis.md) のF01・F02・F03・F04・F05・F07は、原作の計算または状態変更がWPF版で欠落した候補である。原作自身の疑わしい参照や、複数のゲーム仕様が成立する項目とは分けて扱う。

## 提案する決定

| 差分 | 採用する挙動 | 理由と影響 |
| --- | --- | --- |
| F01 | 週初めに路線の週次旅客数・収入・支出・貨物本数・過容量フラグをゼロへ戻す | 今週の需要から毎週計算する。貨物が前週から累積する挙動は終了する。累計収支・定着率・編成割当は保持する |
| F02 | 貨物禁止の長距離経路は貨物本数をゼロとして扱う | 読み込んだシナリオ指定を反映する。旅客・人口の対象からは除外しない |
| F03 | 戦時に直接旅客便を削った直後に負数をゼロへ補正し、残る不足を系統便へ回す | 原作の独立したifを再現する。今回の戦時減算で生じた負数がその週に補正される。必要時は貨物も容量で制限する |
| F04 | 貨物単価の乱数範囲を35～45の両端含みにする | 原作rdの範囲に一致させる。貨物収入の最大単価が1増える |
| F05 | 売却成功時に数量×価格÷10を資金へ加算する | 原作の売却代金を反映する。端数は合計額の除算で切り捨て、単価を先に丸めない。画面の売却見積にも同じ計算を使う |
| F07 | 未割当の系統も安全にリセットでき、二度目のリセットで編成を重複返却しない | 原作で未割当系統を除外する目的を、公開モデルの安全なリセットとして実現する。設備変更途中のnull参照を解消する |

## 代替案

現状を全面的に保存する案は、原作の明確な指定や今週の計算を反映しないため採用しない。一方、原作の状態変更を全面的に再現する案は、疑わしい原作処理まで戻すため採用しない。割当失敗時の原子性、初期保有数、競合・技術・目標の補正、少数編成費用、廃止と再建は今回の決定に含めない。

## 設計仮説との関係

[Astraの設計仮説](../design-hypotheses.md) を原作ソースの観測事実とは別に記録した。週次需要とシナリオ指定、見積と入金の一致、安全な未割当リセットの仮説が、今回の修正判断を補強する。仮説単独ではこの採用範囲を広げない。

## 検証

- `dotnet test whr_wpf.sln --no-restore --verbosity quiet`: 147件成功、失敗・スキップ0。新規24ケースは `OriginalStatePortTests` に集約した。
- 貨物の2週計算・過容量から需要ゼロ・禁止/許可経路の両順序・禁止経路の旅客維持を確認した。
- 戦時の直接便のみ、直接便から系統便への残差、複数系統、貨物の容量制限と投入編成数保持を確認した。
- 単価35・45の運賃計算と乱数収入の範囲、売却端数・0/全数/不足/負数/null・intを超える乗算・画面見積を確認した。
- 未割当、割当済みの二度リセット、未割当/割当済み混在と共有系統の設備変更を確認した。
- 回収した6モードについて48週後の全60都市の人口が、原作ソース由来の参照計算と一致した。確認用プロジェクトと配布物はGit対象外で、原作実行ファイルとの照合ではない。
- Astraが実装・テスト網羅・ADRとの整合を仕上げレビューし、P1/P2指摘なし。原作ソース・採用判断のレビューも別段階で実施済み。
