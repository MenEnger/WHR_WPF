# ADR 0016：運行設定の初期拒否を表示から分離する

- 状態：採用
- 日付：2026-10-07
- 関連：Issue #26、#28

## 背景

路線・系統の運行設定の初期拒否5箇所が、日本語InvalidOperationException.Messageで画面へ理由を伝える。UIや将来の操作窓口が文章に依存せず、対象と拒否理由・判定値を扱えるようにする。

## 判断

直接/系統と拒否理由を不変recordへ保存し、専用のInvalidOperationException派生型で伝える。対象名と要求本数を保存し、事前編成不足だけ必要編成数・比較左辺の余剰数・右辺の既存不足計算結果を保存する。可変モデルや未知編成の名前・価格を追加取得しない。

数量は既存評価順の観測値であり、同時点の整合値とはしない。必要数計算→左辺HeldUnits→右辺CalcMissingCompositionsの評価順・回数を維持し、比較もそのまま行う。既知の余剰二重評価を補正せず、CalculatedMissingUnitsを実際の不足数と解釈し直さない。

Viewのformatterが既存3文章を作り、ViewModelBaseで一般InvalidOperationExceptionより先に専用型を捕捉する。適合拒否、系統の頻度判定とダイヤ復元、旧割当解除、Use段階の数量不足、途中状態は維持する。

## 代替案

- 日本語Messageに理由を追加：Modelの表示責務が残るため不採用。
- 共通割当サービスや新しい検査APIを導入：今回の5拒否の分離には必要がなく、範囲と保守負担が増えるため不採用。
- 不足式や割当解除順も修正：挙動の仕様判断を伴うため今回は不採用。
- 数量を一度だけ読むよう計算を統合：任意ICompositionのgetterや計算回数が変わるため今回は不採用。

## 影響

操作シグネチャと基底例外catchの互換を維持する。厳密な例外型比較・日本語Message依存は移行が必要。数量は初期不足以外ではnull。対象自身の名前はnullも許容し、新しい入力検査は追加しない。

責務分離・可読性・保守性のため、5拒否と1formatterに限定する。成功・適合拒否・解除後Use拒否は既存テストを再利用する。仕様・影響・設計・検証はdocs/design/service-setting-refusals.md。実ダイアログは未操作、既知の挙動問題は別途判断する。
