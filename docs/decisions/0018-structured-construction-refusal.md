# ADR 0018：建造拒否を表示から分離する

- 状態：採用
- 日付：2026-10-07
- 関連：Issue #26、#28

## 背景

Line.ConstructはCanConstruct falseを日本語InvalidOperationExceptionで伝える。UI外の操作窓口でも建造設定の不適合を文章に依存せず扱う必要がある。

## 判断

拒否された速度・軌道・電化・軌間・レーン数と路線名を不変recordへ保存し、専用のInvalidOperationException派生型で伝える。判定は既存CanConstructをそのまま使用し、対象外の待避線・費用を収集しない。単一の拒否なので理由enumや新しい可否APIは導入しない。

Viewのformatterへ既存文章を移し、共通VMの一般catchより先に専用catchを置く。建設画面の独自catchは資金不足のみのまま維持し、建造拒否の伝播を変えない。

## 代替案

- 内部引数診断として扱う：UI外でも利用者の設定拒否として扱う必要があるため不採用。
- CanConstructの拒否理由を細分化する：既存のbool判定を重複実装するかAPI変更が必要なため今回は不採用。
- 建設画面のcatchと確認フローも統合：既存の拒否伝播と画面寿命が変わるため別変更とする。

## 影響

操作シグネチャ・bool API・基底catchの互換は維持し、具体例外型・日本語Message依存は移行が必要。費用計算回数・支払・成功時の設備変更と通知、拒否優先は維持する。

残る算出式・未定義値・引数範囲等の例外は内部診断として今回構造化しない。CannotContinueExceptionのモード適用不整合は、読み込み診断保存へ未接続で別途判断する。分類とUI表示への到達性は区別する。

仕様・影響・設計・検証はdocs/design/construction-refusal-boundary.md。既存の成功・資金不足試験を再利用し、1拒否に必要な境界へ限定して可読性と保守性を保つ。
