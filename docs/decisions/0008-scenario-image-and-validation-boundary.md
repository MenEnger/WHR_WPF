# ADR 0008：シナリオ地図と検証エラーの表示境界

日付: 2026-10-06
状態: 採用。ADR 0006の段階的な実装。関連Issue #25・#28。

## 背景と判断

`GameInfo` がWPFの `BitmapImage` を保持し、シナリオ読込が画像生成・検証ダイアログ・アプリ終了を直接行っていた。ゲーム本体をWPFから抽出する最初の段階として、状態は `MapImagePath` に参照先だけを持ち、WPF側の `ScenarioPresentation` が画像と検証エラーの表示文言を生成する。

画像は `OnLoad` で取り込み、ストリームを閉じて表示側で保持・再利用する。メニューの `ScenarioPresentation.LoadScenario` では、設定検証後・CSV解析前の地図参照通知でUI側が画像を確保する。読込側の通知はパスのみを渡す `Action<string>` とし、画像を使わない利用側は省略できる。WPF型・部分的なゲーム状態を通知に含めない。

メニューで作ったUI専用の `ScenarioPresentation` を難易度・モード選択・ゲーム画面へ引き継ぎ、画像を再読込しない。画像の欠落・破損は従来の読込エラーとして案内する。ゲーム状態とファイル解析だけなら地図画像なしでも扱える。

不正なシナリオ版・基準年では、読込側が理由・ファイル・項目・値を持つ `ScenarioValidationException` を投げる。ダイアログと終了判断はUIへ移す。UIでは従来の文言と終了方針を維持する。読込側は失敗時に以後の解析を実行せず、部分的なゲーム状態を返さない。

## 代替案

- WPF画像を汎用 `object` にする：型への依存を隠すだけで、状態が画像の寿命を持ち続けるため採用しない。
- 初段階から画像バイト列を本体に保持する：現状のローカルファイル参照には不要なI/O責務が増えるため採用しない。将来のWeb・新形式では参照情報の形式を再検討できる。
- すべての読込例外を共通の結果型へ変換する：エラー分類と診断情報の設計を一度に広げるため、今回の範囲に含めない。I/O・数値解析などの例外は現状どおりUIへ伝える。

## 影響と残る範囲

版・基準年の検証は、従来のShutdown呼出し後の処理続行に頼らず例外で確実に中断する。設定検証・地図確保・CSV解析の順序を維持する。地図確保後に元ファイルが削除・置換されても、その時点で取り込んだ画像を引き継ぐ。CSV全体を同時点で固定する仕組みを追加したという意味ではない。数式・費用・運行・モード設定は変更しない。旧セーブ形式は既に利用不可であり、移行機能は追加しない。

Issue #25の全完了ではない。モデルの診断出力、ApplicationUtil内のI/OとUIの整理、読込診断全体は後続に残す。本体プロジェクトの抽出、構造化シナリオ入力、週次通知・表示整形・共通操作窓口も別段階である。現在のテストプロジェクトはWindows向けのまま。

## 検証

分離前に4ケースでUTF-8・Shift_JIS、参照の紐付け、補正とモード適用、欠落ファイルと数値解析失敗を記録した。分離後は検証境界値・画像なしの読込・表示側の画像拒否と文言を含む21ケース、全190件が成功した。STA上の実際のGamePage描画で画像の再利用と元ファイルの解放、画像読込後・ゲーム開始前に元ファイルを削除しても各選択画面を構築して開始できることを確認した。CSV解析前の画像削除・置換、設定・画像・CSVのエラー優先順とCSV失敗時のファイル解放も検査した。画面遷移・ダイアログ・アプリ終了の実操作は未検証。
