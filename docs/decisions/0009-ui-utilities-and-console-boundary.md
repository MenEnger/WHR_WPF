# ADR 0009：UIユーティリティとコンソール出力の境界

日付: 2026-10-06
状態: 採用。ADR 0006の段階的な実装。関連Issue #25・#28。

## 背景と判断

`ApplicationUtil` は終了確認・保存不可の案内と、呼び出しのないテキスト読込・旧バイナリ保存APIを同居させていた。UI操作に使う `Exit`・`ForceExit`・`LoadData`・`SaveData` を残し、クラスを `View/ApplicationUtil.cs` へ移す。名前空間・呼び出し方・文言・終了判断は維持する。

`LoadFileLines`・`LoadFromBinaryFile`・`SaveToBinaryFile` はリポジトリ全体に呼び出しがないため削除する。使われないファイル操作を新しいI/Oクラスへ移し替えて維持しない。今後のセーブ・ロードはIssue #9で形式と責務を決めて実装する。保存機能の復旧や旧データの移行は今回行わない。

`Line.CalcBestSpeed(null)` の標準エラー出力と、シナリオ読込成功時の標準出力を除去する。未割当の速度0は通常の計算結果、読込成功は戻り値で確認できる。モデルとファイル解析はホストのコンソールへ直接出力せず、異常は既存の例外を呼び出し側へ伝える。UIの診断出力とダイアログはUI側に残す。

## 代替案と影響

- すべての診断を新しいロガーへ置換する：今回の出力は通常の結果で足りるため、不要な本体依存を増やさない。必要な診断基盤は別途設計する。
- 未使用APIをI/Oクラスへ移す：利用されていない機能の維持が目的になり、本体抽出の前提が増えるため採用しない。

削除した公開メソッドをリポジトリ外から直接呼ぶコードは互換性を失う。本アプリ内には呼び出しがないことを確認した。費用・速度計算・ゲーム状態・読込順とエラー判定・画像寿命は変更しない。旧テキスト読込の `throw e` も削除され、既存CA2200警告が解消する。

## 検証と残る範囲

追加2ケースは修正前に直接出力で失敗し、修正後は未割当の速度0・状態保持、シナリオ読込とモード適用の結果を検査しつつ標準出力・標準エラーの混入を拒否する。コンソールの差し替えは非並列テストで行い、失敗時も元の出力先へ戻す。既存の読込・WPF描画テストを含め全192件が成功した。

Model・UtilからSystem.Windows、MessageBox、ApplicationUtil、Shutdown、Consoleへの直接参照がなくなった。プロジェクト抽出前のソース上の境界であり、WPF非依存のビルドを実現したという意味ではない。

Issue #25の読込診断全体の構造化、#26の通知・拒否理由、#27の表示整形、#28の本体プロジェクト抽出は未完了。UIの終了・保存不可の案内は呼び出しとビルドで確認し、実ダイアログ・アプリ終了は未操作。
